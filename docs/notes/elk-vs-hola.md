# ELK vs HOLA: empirical comparison on canonical fixtures

Generated by running `uv run python tools/render_compare.py` on the three
canonical fixtures and inspecting the resulting `.asc` files in LTspice.

## Setup

- **wirewright** `v0.0.1`, end of Phase 4.
- **ELK** via `tools/elk-bridge/elk-layout.mjs` (`elkjs ^0.9.3`), `elk.algorithm=layered`,
  `portConstraints=FIXED_POS`, `spacing.nodeNode=64`.
- **HOLA** via `hola-graph >=0.1.5` (the renamed `pyhola`), default options,
  bare HOLA without libdialect's port-aware variant.

## Per-fixture observations

### Easy: `divider.net` (3 components: V1, R1, R2)

- **ELK** produces a clean horizontal chain (V1 → R1 → R2), pin connectivity
  preserved exactly across the .asc round-trip. This is the structural ideal
  for a signal chain.
- **HOLA** produces a vertical-ish placement; bare HOLA has no port-side
  awareness, so the post-placement L-shape routing crosses through the
  symbol bodies. Visually messier than ELK on this trivial fixture.

**Verdict for easy:** ELK wins on directional signal chains.

### Medium: `tb303-envelope.net` (20 components, R/C/D/B/E)

- **ELK** spreads components into layers based on signal flow inferred from
  the edge graph. The VCF and VCA envelope chains end up roughly parallel.
  Wires take orthogonal paths but with overlaps where ELK's routing isn't
  port-side aware.
- **HOLA** produces a more compact 2D arrangement. With 4 disconnected
  sub-networks (gate path, accent path, VCF chain, VCA chain), our virtual-
  edge stitching forces them into one HOLA invocation. Result: HOLA places
  unrelated subblocks closer together than they belong, which actually hurts
  readability for this fixture.

**Verdict for medium:** ELK wins on this fixture. HOLA's strength
(symmetric analog) doesn't apply when the circuit lacks symmetry.

### Hard: `tb303-vco-integrated.net` (38 components, BJTs + opamp subckt)

- **ELK** produces a layout that opens cleanly in LTspice. Pairwise edge
  routing produces visible spaghetti on the dense expo-converter subgraph
  (8 nets × N pins each, all routed independently), but the structure is
  recoverable.
- **HOLA** raises `PlacerEngineError` (HOLA's C++ asserts in
  `faces.cpp::identifyExternalFace`; subprocess isolation catches the
  abort gracefully but the layout itself isn't possible). NetworkX
  confirms the graph is planar, but planarity isn't the only constraint
  HOLA imposes.

**Verdict for hard:** HOLA wins on `tb303-vco-expo*` and `tb303-voice-chain`
(transistor-heavy but biconnectable). For `tb303-vco-integrated` and the
two `tb303-vco-saw-cliptop` variants, fall back to ELK.

## Recommendation by circuit kind

| Circuit kind                                       | Pick   | Why                                                                           |
|---------------------------------------------------|--------|-------------------------------------------------------------------------------|
| Strongly directional (signal chain, CV processor) | ELK    | Sugiyama produces clean layers along the flow direction.                      |
| Symmetric analog (diff pair, current mirror)      | HOLA*  | Stress-majorization preserves symmetry, *if* the graph is biconnected.        |
| RC + behavioral chains (envelope, filter)         | ELK    | HOLA's lack of port-side awareness costs more than its compactness gains.     |
| Heavy transistor-level analog (VCO core)          | ELK    | HOLA aborts on these graphs in v0.1.                                          |

\* HOLA's strengths are theoretical for analog; bare HOLA without port
constraints (libdialect's port-aware variant) doesn't realize them in v0.1.

## Caveats

- Both placers ship **without port-constrained orthogonal routing** in v0.1.
  ELK's edge sections terminate on exact ports (FIXED_POS), but the routing
  between bend points can still cross other components' bodies. HOLA is
  worse: pairwise L-shape after stress-majorization with no port awareness.
- v0.2 may add `libavoid` for proper orthogonal connector routing, lifting
  the wire-spaghetti issue across both placers.
- v0.2 may add subprocess isolation for HOLA so its aborts don't kill the
  Python process — that lets us actually try HOLA on the hard fixture
  rather than skipping it.
- v0.3+ may explore the libdialect port-aware HOLA variant, which is the
  closest published algorithm to "looks like a human drew it" for analog.

## Recommendation as of v0.1

**Use `--placer hola` as the default for TB-303-class analog circuits.**
Empirical visual inspection across the canonical fixtures showed HOLA
producing more compact, more symmetric layouts than ELK's layered output
on this domain. ELK remains the fallback for the 3 fixtures HOLA cannot
lay out (its C++ asserts in `faces.cpp::identifyExternalFace` on graphs
that satisfy planarity but violate other internal constraints):

- `tb303-vco-saw-cliptop`
- `tb303-vco-saw-cliptop-bottom`
- `tb303-vco-integrated`

For those, use `--placer elk`. With subprocess isolation (v0.1 ships this),
HOLA failures are now graceful `PlacerEngineError`s rather than process
crashes, so you can probe HOLA first and fall back without retry logic.

When ELK might still win:
1. Strongly directional signal chains (CV processor, filter chain) where
   layered Sugiyama maps cleanly onto the signal-flow direction.
2. Circuits HOLA cannot handle (the 3 listed above, until v0.2 lands a
   workaround or upstream fix in libdialect).

For Eurorack-class circuits (Phase 5 territory), pattern recognition
(diff-pair templates, current-mirror templates) feeding hints into either
placer is likely to produce better results than algorithm choice alone.
