# v0.2 backlog

Items deferred from v0.1 with their rationale, ranked by expected leverage
on TB-303-class output quality (based on user empirical preference for HOLA
output as of v0.1 release).

## Tier 1 — high-leverage placer fixes

### HOLA hint integration (HOLA respects `pinned`)

**Why:** HOLA is the user's preferred placer; `--use-patterns` currently
only feeds hints to NaivePlacer, so HOLA users get no benefit from the
pattern recognition layer. Diff-pair/current-mirror idioms in TB-303
circuits would visibly improve with template-pinned positions.

**Approach:** `hola_graph.HolaGraph.add_node` accepts `x` and `y` as initial
positions. Investigate whether HOLA respects them as pinned coordinates
during `layout()` or just as starting points for the iterative solver.
If respected: pass through. If not: post-process — let HOLA layout
unpinned, then translate the entire result so pinned components land at
their target coordinates (preserves relative layout).

**Estimate:** 1–2 sessions.

### HOLA layout for the 3 hard-fixture aborts

**Why:** `tb303-vco-saw-cliptop`, `tb303-vco-saw-cliptop-bottom`, and
`tb303-vco-integrated` cannot be laid out by HOLA in v0.1. Subprocess
isolation makes them fail gracefully (no Python crash), but the user
cannot use HOLA on these circuits at all.

**Approach options:**
1. **Pre-process the graph** to satisfy HOLA's structural requirements
   (likely biconnectivity around articulation points). Add virtual edges
   to bridge cut vertices, similar to how disconnect-stitching works.
   May produce odd layouts but unblocks HOLA.
2. **Upstream fix:** report to `shakfu/hola-graph` or upstream Adaptagrams
   `libdialect` so the C++ assertion becomes a recoverable error. Long
   tail; not within wirewright's control.
3. **Auto-fallback:** when HOLA raises, retry with ELK silently. Already
   possible at the CLI layer; a `--placer auto` option would formalize.

**Estimate:** option 1 ≈ 1 session of trial-and-error; option 2 unbounded;
option 3 ≈ 30 minutes.

### ELK pinned-hint support

**Why:** Currently ELK ignores `pinned` hints. With patterns + ELK, users
get pattern detection but no positional benefit. Lower priority than HOLA
hint integration since HOLA is the preferred placer.

**Approach:** Investigate `org.eclipse.elk.layered.crossingMinimization.semiInteractive`
combined with per-node `x`/`y` and `org.eclipse.elk.layered.layering.layerConstraint`.
The earlier in-session smoke showed `interactiveLayout=true` alone doesn't
respect coordinates; deeper exploration needed. Alternative: two-pass —
use `elk.algorithm: fixed` for matched components, then run `layered`
on the rest with the fixed positions as boundary conditions.

**Estimate:** 2–3 sessions; may require a small JS-side change to the bridge.

## Tier 2 — pattern library expansion

The 8+ templates deferred from Phase 5 (per
`docs/notes/pattern-coverage.md`):

- `diff_pair_nmos` / `diff_pair_pmos` (mechanical clones once diff_pair_npn matcher works)
- `current_mirror_nmos` / `current_mirror_pmos` (same)
- `cascode_npn` / `cascode_nmos` (3-component stack)
- `common_source_nmos` (NMOS analog of CE)
- `opamp_inverting` / `opamp_noninverting` (needs opamp-as-symbol vs opamp-as-flattened-subckt design call)
- `opamp_sallen_key_lpf` (5-component active filter)
- `bjt_diff_amp_full` (composite: diff pair + tail current source + mirror load)
- `tb303_ladder_rung` (the headline TB-303 idiom; high user value)
- `expo_converter_2t` (2-transistor + thermistor/PTC)

**Estimate:** 30 lines of YAML each + matcher test. ~1 session for all 12.
Higher-value templates (`tb303_ladder_rung`, `bjt_diff_amp_full`) may need
fixture authoring.

## Tier 3 — quality and infra

### Routing improvements

Both ELK and HOLA emit pairwise L-shape wires that frequently cross
component bodies. The `routing/orthogonal.py` module is the right place
to add libavoid (Adaptagrams' object-avoiding orthogonal connector router)
or similar.

### Hand-drawn fixture round-trip

Phase 1 DoD has a deferred bullet: hand-drawn `.asc` for the canonical
fixtures + round-trip test. Once user authors them in LTspice, wire up
the Phase 1 round-trip integration test.

### `parse/ltspice_asc.py` use-case

The `.asc` parser exists for round-trip validation. It also enables the
"manual edit → diff → learn" loop the user originally proposed: render
via ELK/HOLA → edit in LTspice → re-parse → diff against placer output
to identify systematic placer improvements.

## Tier 4 — won't fix in v0.2

- Hierarchy preservation (subcircuits stay flattened; spec is explicit).
- LLM-based placement (out-of-scope per ADR; EEschematic side experiment only).
- Custom symbol generation.
- PCB layout.
